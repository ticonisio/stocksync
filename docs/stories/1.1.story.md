## Story
**As a** desenvolvedor,
**I want** o projeto scaffolded com Next.js 14+ App Router, Prisma, CI/CD e deploy na Vercel configurados,
**so that** a equipe possa começar a construir features em uma base sólida, deployável e com pipeline de qualidade funcionando.

## Acceptance Criteria
1. Next.js 14+ App Router inicializado com TypeScript 5.x, Tailwind CSS 3.x e ESLint configurados
2. Prisma 5.x configurado e conectado à instância PostgreSQL do Supabase (com `DATABASE_URL` + `DIRECT_URL` para connection pooling)
3. Variáveis de ambiente documentadas em `.env.example` com todas as chaves necessárias e comentários explicativos
4. Health check endpoint `GET /api/health` retorna `200` com `{ status: "ok", timestamp: "<ISO 8601>" }`
5. Projeto faz deploy com sucesso na Vercel em push para `main` (CI/CD via GitHub integration)
6. Pipeline CI executa `lint` + `typecheck` + `test` em todo PR via GitHub Actions (`.github/workflows/ci.yaml`)

## Dev Notes

### Tech Stack Relevante
- **Next.js**: 14.x App Router — monolito modular (frontend + backend API Routes no mesmo repo)
- **TypeScript**: 5.x — strict mode habilitado
- **Tailwind**: 3.x — dark mode via `class` strategy; paleta definida na front-end-spec
- **Prisma**: 5.x — ORM para PostgreSQL; `DATABASE_URL` (PgBouncer) + `DIRECT_URL` (direto para migrations)
- **Supabase**: PostgreSQL + Realtime — `@supabase/supabase-js` apenas para Realtime client; Prisma faz tudo de DB
- **NextAuth.js**: 4.x — autenticação (Story 1.2 e 1.3 implementam os providers)
- **Vitest**: testing framework — mais rápido que Jest, melhor DX com TypeScript

### Singleton Prisma Client
```typescript
// src/lib/prisma.ts
import { PrismaClient } from '@prisma/client';

const globalForPrisma = globalThis as unknown as { prisma: PrismaClient };

export const prisma =
  globalForPrisma.prisma ??
  new PrismaClient({
    log: process.env.NODE_ENV === 'development' ? ['query', 'error', 'warn'] : ['error'],
  });

if (process.env.NODE_ENV !== 'production') globalForPrisma.prisma = prisma;
```

### Prisma + Supabase Connection
- **`DATABASE_URL`**: Usa PgBouncer (pooling) — para a aplicação em produção
- **`DIRECT_URL`**: Conexão direta ao PostgreSQL — APENAS para `prisma migrate`
- Em `schema.prisma`: `datasource db { url = env("DATABASE_URL"); directUrl = env("DIRECT_URL") }`

### Decisões de Arquitetura Relevantes (não reabrir)
- Monolito modular — sem serviços separados
- Prisma como única camada de acesso ao banco (Supabase client apenas para Realtime)
- Absolute imports via `@/*` (tsconfig paths)
- Node.js 20+ requerido
