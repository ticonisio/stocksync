# Story 9.5: Fix — Cards do Dashboard não atualizam em tempo real com pedidos

## Story
**As a** lojista,
**I want** que os cards "Custo do Estoque" e "Valor do Estoque" atualizem automaticamente quando um pedido entra,
**so that** eu veja o impacto financeiro de cada venda em tempo real sem precisar recarregar a página.

## Problema
Atualmente, quando um webhook `orders/paid` chega:
1. O `availableStock` é decrementado atomicamente no banco (OK)
2. O hook `useInventoryRealtime` detecta a mudança na tabela `Variant` e atualiza as linhas da tabela (OK)
3. **Mas os 6 cards de resumo do dashboard (Produtos, Variantes, Disponível, Reservado, Custo do Estoque, Valor do Estoque) são computados server-side no carregamento da página e NÃO recalculam quando o realtime dispara** (BUG)

Os cards de "Custo do Estoque" (`Σ availableStock × averageCost`) e "Valor do Estoque" (`Σ availableStock × price`) ficam defasados até o próximo F5.

## Acceptance Criteria
1. Quando o realtime detecta uma atualização de `Variant` (mudança de stock), os cards **"Disponível"**, **"Reservado"**, **"Custo do Estoque"** e **"Valor do Estoque"** recalculam automaticamente a partir dos dados no Zustand store — sem reload da página
2. O card "Custo do Estoque" recalcula: `Σ(variant.availableStock × variant.averageCost)` para variantes com `averageCost != null` presentes no store
3. O card "Valor do Estoque" recalcula: `Σ(variant.availableStock × variant.price)` para variantes com `price != null` presentes no store
4. O card "Disponível" recalcula: `Σ(variant.availableStock)` a partir do store
5. O card "Reservado" recalcula: `Σ(variant.reservedStock)` a partir do store
6. Se o hook de realtime recebe um campo `averageCost` ou `price` na payload (além de stock), esses valores também são atualizados no Zustand
7. Os valores iniciais dos cards continuam vindo do server (SSR) — o recálculo client-side só ocorre após eventos de realtime
8. Formatação BRL mantida (`Intl.NumberFormat`) nos cards recalculados
9. Proteção cross-store mantida via `storeId` no filtro do canal Supabase

## Scope
### IN
- Tornar os 4 cards numéricos reativos (Disponível, Reservado, Custo, Valor)
- Expandir o payload do `useInventoryRealtime` para incluir `averageCost` e `price`
- Adicionar computed values derivados no Zustand store ou via selector
- Cards "Produtos" e "Variantes" permanecem estáticos (contagem não muda com pedidos)

### OUT
- Rewrite completo do dashboard para client component
- Recálculo de urgency cards em real-time (escopo separado)
- Mudanças no webhook handler ou schema

## Technical Notes
- O dashboard page é um Server Component (RSC) — os cards precisam ser extraídos para um Client Component que leia do Zustand
- O `useInventoryRealtime` atualmente só extrai `availableStock`, `reservedStock`, `committedStock` do payload — precisa incluir `averageCost` e `price`
- O Zustand store `inventoryStore` já tem `products: ProductWithRollup[]` que contém os rollups — o recálculo pode ser um selector derivado
- O Supabase Realtime já envia todos os campos da row no `payload.new` — só precisamos ler os campos adicionais
