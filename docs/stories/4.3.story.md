## Story
**As a** lojista,
**I want** configurar grupos de lead time para meus fornecedores e ver quais produtos precisam ser recomprados com urgência,
**so that** eu possa agir antes que o estoque chegue a zero, cruzando a velocity de vendas real com o prazo de entrega do fornecedor.

## Acceptance Criteria
1. Usuário pode **criar, editar e deletar** grupos de lead time (nome + prazo em dias) via seção "Grupos de Lead Time" na página `/settings`
2. Usuário pode **associar produtos a um grupo** via modal de seleção com checkboxes; um produto pode pertencer a no máximo um grupo (troca de grupo remove associação anterior)
3. Produto pode ter **lead time individual** (`leadTimeOverrideDays`) que sobrescreve o prazo do grupo ao qual pertence; configurável via input na modal de associação; anulável (campo vazio = usar prazo do grupo)
4. **Buffer de alerta:** cada grupo tem `bufferDays` — se não configurado, calculado automaticamente como `Math.max(7, Math.round(leadTimeDays * 0.15))`
5. **API `GET /api/urgency`** aceita `?period=7d|30d|90d` (default `30d`) e retorna `{ items: UrgencyItem[], summary: { critical, warning, ok } }` com:
   - `urgency = Math.floor(totalAvailableStock / velocityPerDay) - leadTimeDays` (dias sobram após lead time)
   - Status: `CRÍTICO` (urgência ≤ 0), `ATENÇÃO` (urgência ≤ effectiveBuffer), `OK` (urgência > effectiveBuffer)
   - Apenas produtos com velocity > 0 E lead time configurado (grupo ou override) aparecem
   - Ordenados por urgência ASC (mais crítico primeiro)
6. **Aba "Tempo de Entrega"** (`/lead-time`) exibe a lista de urgência com badge colorido por status, dias restantes estimados, velocity e lead time efetivo; estado vazio amigável quando sem dados
7. Proteção cross-store: todos os endpoints verificam `storeId` do usuário autenticado; 401 sem sessão, 404 sem store

## Dev Notes

### Schema Já Existente — Não Criar Migrations

O schema Prisma já possui todos os modelos necessários:
- `LeadTimeGroup`: `id, storeId, name, leadTimeDays, bufferDays (Int?), products, createdAt, updatedAt`
- `ProductLeadTimeGroup`: junction table `(productId, leadTimeGroupId)` — `@@id([productId, leadTimeGroupId])`
- `Product.leadTimeOverrideDays`: `Int?` — já no schema; null = usar grupo

**Não criar novas migrations nesta story.** Todos os campos já existem.

### Lógica de Urgência

```typescript
// src/services/inventory/urgency-service.ts

export interface UrgencyItem {
  productId: string;
  title: string;
  topVariantTitle: string;
  velocityPerDay: number;
  totalAvailableStock: number;
  leadTimeDays: number;          // efetivo (override ?? group)
  effectiveBuffer: number;
  urgency: number;               // dias sobram após cumprir lead time
  status: 'CRÍTICO' | 'ATENÇÃO' | 'OK';
}

// Fórmula:
// effectiveLeadTimeDays = product.leadTimeOverrideDays ?? group.leadTimeDays
// effectiveBuffer = group.bufferDays ?? Math.max(7, Math.round(effectiveLeadTimeDays * 0.15))
// urgency = Math.floor(totalAvailableStock / velocityPerDay) - effectiveLeadTimeDays
// CRÍTICO: urgency <= 0
// ATENÇÃO: urgency <= effectiveBuffer
// OK: urgency > effectiveBuffer
```

### Proteção Cross-Store e Associação Exclusiva

- Toda query usa `storeId: store.id` (derivado de `session.user.id → store.findFirst`)
- Ao atribuir produto a grupo, remover primeiro de qualquer grupo anterior (associação exclusiva 1 produto : 1 grupo)
- Usar `prisma.$transaction()` na Task 4 para atomicidade

### Buffer Auto

```typescript
const effectiveBuffer = group?.bufferDays ?? Math.max(7, Math.round(effectiveLeadTimeDays * 0.15));
// Ex: leadTimeDays=30 → 30*0.15=4.5 → Math.round=5 → Math.max(7,5)=7
// Ex: leadTimeDays=60 → 60*0.15=9 → Math.max(7,9)=9
```

### Divisão por Zero

`velocityPerDay === 0` → pular produto (não calcular urgência). Nunca dividir por zero.

### Pattern de Página `/lead-time`

Mesmo padrão de `/insights/page.tsx`: Server Component, chamada direta ao service (não HTTP interno), `searchParams.period`.

### Componentes Reutilizáveis

- `PeriodSelector` de `@/components/insights/PeriodSelector` — reusar diretamente sem duplicar
- Padrão de `InsightCard` para referência de UrgencyCard (Card + Badge + layout flex)

### Tech Stack Relevante
- **SWR:** `useSWR` + `mutate` para CRUD no LeadTimeGroupsManager (Client Component)
- **Zod:** Validação no body das rotas POST/PUT
- **Dialog/AlertDialog:** shadcn/ui — já instalado
- **prisma.$transaction():** Associação exclusiva de produtos a grupos

### Pré-requisito: Story 4.1 Concluída
Esta story **depende dos dados de `SalesVelocity`** gerados pela Story 4.1. Sem velocity, a lista de urgência será vazia mesmo com grupos configurados.
