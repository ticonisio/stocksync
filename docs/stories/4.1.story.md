## Story
**As a** lojista,
**I want** ver a velocidade de vendas de cada variante e produto,
**so that** eu possa entender o ritmo de saída do estoque e tomar decisões de recompra baseadas em dados reais.

## Acceptance Criteria
1. Velocity calculada por variante para os períodos 7d, 30d e 90d, baseada em pedidos com status `PAID`
2. Fórmula: `velocityPerDay = unitsSold / periodDays` (7, 30 ou 90 dias)
3. Rollup por produto = soma das velocities das variantes do produto
4. Velocity recalculada automaticamente após cada pedido pago processado (webhook `orders/paid`)
5. Variantes sem vendas no período exibem velocity `0` (registro com `unitsSold: 0, velocityPerDay: 0`)
6. Exibida na página de detalhe do produto (Story 3.5) com selector de período — sem alteração de UI, dados já consumidos
7. Armazenada via UPSERT na tabela `SalesVelocity` — evita recálculo por request

### Tech Stack Relevante
- **Prisma:** `salesVelocity.upsert` com `where: { variantId_period: { variantId, period } }`
- **SalesVelocity schema:** `@@unique([variantId, period])` — chave composta gerada pelo Prisma como `variantId_period`
- **Next.js 14:** API Route em `src/app/api/velocity/recalculate/route.ts`
- **Webhook handler:** `src/app/api/shopify/webhooks/route.ts` — modificar `processOrderPaid` ou chamar após ele

### Serviço de Cálculo
```typescript
// src/services/velocity/calculateVelocity.ts

const PERIOD_DAYS: Record<string, number> = {
  '7d': 7,
  '30d': 30,
  '90d': 90,
};

export async function calculateAndSaveVelocity(
  storeId: string,
  variantIds?: string[]
): Promise<void> {
  // Buscar variantes da store (ou apenas as fornecidas)
  const variants = await prisma.variant.findMany({
    where: {
      storeId,
      ...(variantIds ? { id: { in: variantIds } } : {}),
    },
    select: { id: true },
  });

  for (const variant of variants) {
    for (const [period, days] of Object.entries(PERIOD_DAYS)) {
      const since = new Date();
      since.setDate(since.getDate() - days);

      // Agregar unidades vendidas no período
      const result = await prisma.orderItem.aggregate({
        where: {
          variantId: variant.id,
          order: {
            storeId,
            status: 'PAID',
            createdAt: { gte: since },
          },
        },
        _sum: { quantity: true },
      });

      const unitsSold = result._sum.quantity ?? 0;
      const velocityPerDay = unitsSold / days;

      await prisma.salesVelocity.upsert({
        where: { variantId_period: { variantId: variant.id, period } },
        update: { unitsSold, velocityPerDay, calculatedAt: new Date() },
        create: { variantId: variant.id, storeId, period, unitsSold, velocityPerDay },
      });
    }
  }
}
```

### Integração no Webhook (modificação mínima)

```typescript
// Após processOrderPaid — adicionar:
if (topic === 'orders/paid') {
  await processOrderPaid(store.id, payload);

  // Recalcular velocity das variantes afetadas (fire-and-forget com try/catch)
  try {
    const shopifyVariantIds = payload.line_items.map((i) => String(i.variant_id));
    const variants = await prisma.variant.findMany({
      where: { storeId: store.id, shopifyVariantId: { in: shopifyVariantIds } },
      select: { id: true },
    });
    const internalIds = variants.map((v) => v.id);
    await calculateAndSaveVelocity(store.id, internalIds);
  } catch (err) {
    console.error('[webhook] velocity recalculation failed:', err);
  }
}
```

### API de Recálculo Manual
```typescript
// src/app/api/velocity/recalculate/route.ts
export async function POST(req: Request) {
  const session = await getServerSession(authOptions);
  if (!session?.user?.id) return NextResponse.json({ error: 'Unauthorized' }, { status: 401 });

  const store = await prisma.store.findFirst({ where: { userId: session.user.id } });
  if (!store) return NextResponse.json({ error: 'Store not found' }, { status: 404 });

  await calculateAndSaveVelocity(store.id);

  return NextResponse.json({ ok: true });
}
```

### Rollup por Produto (AC 3)
O schema armazena velocity **por variante** (`SalesVelocity` com `variantId`). Não há tabela de velocity a nível de produto.

O rollup é **computado dinamicamente** no momento da leitura:
- **Dashboard (Story 3.x):** soma `velocityPerDay` de todas as variantes do produto na camada de UI ou API
- **Story 4.2 (Produtos em Alta):** `ORDER BY SUM(sv.velocityPerDay) DESC` na query de listagem
- **Story 4.4 (Urgência):** `velocity_diária = SUM(sv.velocityPerDay WHERE period = '30d')` por produto

**Nenhuma task adicional necessária nesta story** — a velocity por variante já é a fonte de verdade; o rollup é derivado on-demand pelos consumers.

### Decisões de Arquitetura (não reabrir)
- Serviço em `src/services/velocity/` (não inline na route) — facilita teste unitário isolado e reuso no webhook
- `variantIds` opcional permite recálculo parcial (pós-webhook eficiente) ou total (manual)
- Falha no velocity dentro do webhook é isolada com try/catch — o pedido já foi processado, velocity pode ser recalculada manualmente depois
- AC 6 (exibida na página de detalhe) já implementado na Story 3.5 — SalesVelocity já é lida pela API `GET /api/inventory/[productId]`; esta story apenas popula os dados
- AC 3 (rollup por produto): computado dinamicamente pelos consumers (4.2, 4.4) — não armazenado separadamente
