## Story
**As a** lojista,
**I want** que o estoque seja atualizado automaticamente quando um pedido for pago ou cancelado na Shopify,
**so that** o dashboard reflita sempre o inventário real sem precisar sincronizar manualmente.

## Acceptance Criteria
1. Ao conectar a loja (`POST /api/shopify/connect`), webhooks são registrados na Shopify para os eventos `orders/paid`, `orders/cancelled` e `orders/refunded`
2. Campo `Store.webhooksRegistered` é marcado `true` após registro bem-sucedido; erros de registro são logados mas não bloqueiam o fluxo de onboarding
3. Endpoint público `POST /api/shopify/webhooks` recebe eventos da Shopify e valida a assinatura HMAC-SHA256 via header `X-Shopify-Hmac-Sha256`
4. Requisições com HMAC inválido retornam 401 sem processar o payload
5. Evento `orders/paid`: cria/atualiza `Order` (status `PAID`), cria `OrderItem` por line item, decrementa `availableStock` de cada `Variant` correspondente (mínimo 0)
6. Evento `orders/cancelled` ou `orders/refunded`: atualiza `Order.status`, incrementa `availableStock` de volta para cada variante do pedido
7. Idempotência garantida via `WebhookEvent.@@unique([storeId, shopifyOrderId, eventType])` — evento duplicado é ignorado silenciosamente (retorna 200)
8. Variantes não encontradas no banco são ignoradas (skip) sem abortar o processamento do pedido inteiro

### Registro de Webhooks na Shopify API

```typescript
// src/services/shopify/webhooks.ts
const TOPICS = ['orders/paid', 'orders/cancelled', 'orders/refunded'] as const;

export async function registerWebhooks(storeId: string): Promise<void> {
  const store = await prisma.store.findUniqueOrThrow({ where: { id: storeId } });
  const token = decrypt(store.accessTokenEncrypted);
  const callbackUrl = `${process.env.NEXTAUTH_URL}/api/shopify/webhooks`;

  try {
    for (const topic of TOPICS) {
      const res = await fetch(
        `https://${store.shopifyDomain}/admin/api/2024-01/webhooks.json`,
        {
          method: 'POST',
          headers: {
            'X-Shopify-Access-Token': token,
            'Content-Type': 'application/json',
          },
          body: JSON.stringify({ webhook: { topic, address: callbackUrl, format: 'json' } }),
          signal: AbortSignal.timeout(10000),
        }
      );
      // 422 = webhook already exists for this topic+address — ignore
      if (!res.ok && res.status !== 422) {
        console.error(`Failed to register webhook ${topic}: ${res.status}`);
      }
    }
    await prisma.store.update({ where: { id: storeId }, data: { webhooksRegistered: true } });
  } catch (err) {
    console.error('registerWebhooks error:', err);
    // Do NOT re-throw — webhook failure must not block onboarding
  }
}
```

### HMAC Verification (Crítico para segurança)

```typescript
import crypto from 'crypto';

function verifyHmac(rawBody: Buffer, hmacHeader: string): boolean {
  const secret = process.env.SHOPIFY_WEBHOOK_SECRET;
  if (!secret) return false;

  const computed = crypto
    .createHmac('sha256', secret)
    .update(rawBody)
    .digest('base64');

  // timingSafeEqual evita timing attacks
  const a = Buffer.from(computed);
  const b = Buffer.from(hmacHeader);
  if (a.length !== b.length) return false;
  return crypto.timingSafeEqual(a, b);
}
```

> **CRÍTICO:** O body DEVE ser lido como raw bytes (`req.arrayBuffer()`) ANTES de qualquer `req.json()`. O JSON.parse altera o formato e invalida o HMAC.

### Payload Shopify `orders/paid`

```typescript

interface ShopifyOrderPayload {
  id: number;           // shopifyOrderId
  line_items: Array<{
    variant_id: number; // shopifyVariantId
    quantity: number;
  }>;
}
```

### Processamento de `orders/paid`

```typescript
async function processOrderPaid(storeId: string, payload: ShopifyOrderPayload): Promise<void> {
  const shopifyOrderId = String(payload.id);

  const order = await prisma.order.upsert({
    where: { storeId_shopifyOrderId: { storeId, shopifyOrderId } },
    update: { status: 'PAID' },
    create: { storeId, shopifyOrderId, status: 'PAID' },
  });

  for (const item of payload.line_items) {
    const variant = await prisma.variant.findUnique({
      where: { storeId_shopifyVariantId: { storeId, shopifyVariantId: String(item.variant_id) } },
    });
    if (!variant) continue; // AC 8: skip variantes não sincronizadas

    // OrderItem sem @@unique — usar findFirst antes de criar (idempotência em retries)
    const existingItem = await prisma.orderItem.findFirst({
      where: { orderId: order.id, variantId: variant.id },
    });
    if (!existingItem) {
      await prisma.orderItem.create({
        data: { orderId: order.id, variantId: variant.id, quantity: item.quantity },
      });
    }

    await prisma.variant.update({
      where: { id: variant.id },
      data: { availableStock: Math.max(0, variant.availableStock - item.quantity) },
    });
  }
}
```

> **Nota:** `OrderItem` não tem `@@unique` além do `id`. Idempotência garantida via `findFirst` antes de criar — a camada superior (`WebhookEvent` único) já bloqueia reprocessamento na maioria dos casos.

### Processamento de `orders/cancelled` / `orders/refunded`

```typescript
async function processOrderCancelled(storeId: string, payload: ShopifyOrderPayload, status: 'CANCELLED' | 'REFUNDED'): Promise<void> {
  const shopifyOrderId = String(payload.id);
  const order = await prisma.order.findUnique({
    where: { storeId_shopifyOrderId: { storeId, shopifyOrderId } },
    include: { items: { include: { variant: true } } },
  });
  if (!order) return; // pedido não estava no DB — ignorar

  await prisma.order.update({ where: { id: order.id }, data: { status } });

  for (const item of order.items) {
    await prisma.variant.update({
      where: { id: item.variantId },
      data: { availableStock: { increment: item.quantity } },
    });
  }
}
```

### Identificação da Store pelo Header

### Decisões de arquitetura (não reabrir)
- Webhook endpoint é PÚBLICO (sem session) — segurança exclusivamente via HMAC
- `registerWebhooks` chamado após connect (não após sync) — mais cedo, mais rápido
- Falha no registro não bloqueia onboarding — `webhooksRegistered` fica `false`, pode ser retentado
- `availableStock` mínimo é 0 — estoque negativo não faz sentido para MVP
- `OrderItem` não tem `@@unique` além do `id`; idempotência garantida pelo `WebhookEvent` único que impede reprocessamento
