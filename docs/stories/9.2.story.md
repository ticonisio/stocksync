## Story
**As a** lojista,
**I want** que o sistema tenha a estrutura de dados para registrar importações de produtos com custo unitário e calcular o custo médio ponderado,
**so that** as features de importação de planilha e dashboard de custos tenham uma fundação sólida no banco de dados.

## Acceptance Criteria
1. Modelo `Import` criado no Prisma schema com campos: `id`, `storeId`, `fileName`, `status` (enum: `PENDING`, `PROCESSING`, `DONE`, `ERROR`), `totalRows`, `matchedRows`, `createdAt`
2. Modelo `ImportItem` criado com campos: `id`, `importId`, `rowNumber`, `rawTitle`, `rawSku` (opcional), `quantity`, `unitCost` (Decimal), `matchedProductId` (opcional), `matchedVariantId` (opcional), `matchStatus` (enum: `MATCHED`, `AMBIGUOUS`, `UNMATCHED`), `createdAt`
3. Campo `averageCost` (Float, nullable) adicionado ao modelo `Variant` — valor materializado recalculado a cada importação confirmada
4. Relações configuradas: `Import` → `Store` (many-to-one), `ImportItem` → `Import` (many-to-one), `ImportItem` → `Product` (optional many-to-one), `ImportItem` → `Variant` (optional many-to-one)
5. Índices criados: `Import(storeId)`, `ImportItem(importId)`, `ImportItem(matchedProductId)`, `ImportItem(matchedVariantId)`
6. Migration Prisma executa sem erros (`npx prisma migrate dev`)
7. `prisma generate` gera o client sem erros
8. Dados existentes não são afetados (migration é aditiva, nenhum campo obrigatório sem default)

```prisma
  id               String          @id @default(cuid())

  availableStock   Int             @default(0)

```

### Decisões arquiteturais (validadas por @architect)
- `unitCost` é `Decimal` (não Float) para precisão monetária — Prisma usa `Prisma.Decimal`
- `averageCost` é `Float?` — valor calculado, precisão de Float é suficiente
- Cascade delete: Import → ImportItem (sim), Store → Import (sim), Product/Variant → ImportItem (SetNull, preserva histórico)
- `matchedProductId` e `matchedVariantId` são opcionais — preenchidos durante fase de matching

### Regra de negócio futura (contexto para próximas stories)
- Na confirmação de importação (story futura), o `averageCost` será recalculado:
  ```
  averageCost = Σ(importItem.quantity × importItem.unitCost) / Σ(importItem.quantity)
  ```
- Importação **só pode incrementar** estoque, nunca diminuir (regra hard-coded na API de confirmação)
