## Story
**As a** lojista,
**I want** buscar e filtrar produtos no dashboard,
**so that** eu encontre rapidamente o produto que preciso verificar sem rolar a tabela inteira.

## Acceptance Criteria
1. Campo de busca por nome ou SKU com debounce de 300ms — filtra em tempo real via query ao servidor
2. Filtro de status: Todos / Disponível (availableRollup > 0) / Reservado (reservedRollup > 0) / Esgotado (availableRollup === 0)
3. Ordenação por: Disponível ↑↓, Reservado ↑↓, Nome A-Z / Z-A
4. Filtros e ordenação combinam entre si (busca + status + ordenação simultâneos)
5. Estado dos filtros persistido na URL como query params (`?search=&status=&sort=&order=`)
6. Botão "Limpar filtros" redefine todos os filtros e retorna para estado padrão
7. Contagem de resultados exibida: "Exibindo X de Y produtos"

## Dev Notes

### Insights da Story Anterior (3.2)
- `initialized` flag no `InventoryTable` evita flash de SSR antes do Zustand hidratar — manter esse padrão
- `storeId` já é passado como prop para `InventoryTable` — disponível para uso nos filtros
- `updatedVariantIds` no store Zustand atualiza em tempo real — filtros devem respeitar estado do store

### CRÍTICO: Dual Filter Implementation Pattern
`dashboard/page.tsx` executa **query Prisma diretamente** (não via `/api/inventory`). Portanto os filtros devem ser implementados em **DOIS lugares**:
1. **`dashboard/page.tsx`** — SSR: aceitar `searchParams.search/status/sort/order`, aplicar na query Prisma para o carregamento inicial da página
2. **`src/app/api/inventory/route.ts`** — API Route: aplicar mesmos filtros para o re-fetch do `useInventoryRealtime` após reconexão Realtime

A interface `searchParams` atual em `dashboard/page.tsx` é `{ page?: string }` — deve ser expandida para incluir todos os novos params.

### Tech Stack Relevante
- **Next.js 14 `useSearchParams()`:** leitura de query params no Client Component — requer `<Suspense>`
- **`useRouter().push()`:** atualiza URL sem reload (shallow navigation)
- **shadcn/ui:** `Input`, `Select`, `Button`, `Badge`
- **lucide-react:** `Search`, `ArrowUpDown`, `X` (limpar)

### Hook useDebounce
```typescript
// src/hooks/useDebounce.ts
import { useState, useEffect } from 'react';

export function useDebounce<T>(value: T, delay: number): T {
  const [debouncedValue, setDebouncedValue] = useState(value);

  useEffect(() => {
    const timer = setTimeout(() => setDebouncedValue(value), delay);
    return () => clearTimeout(timer);
  }, [value, delay]);

  return debouncedValue;
}
```

### Componente InventoryFilters (estrutura)
```typescript
// src/components/inventory/InventoryFilters.tsx
'use client';
import { useSearchParams, useRouter } from 'next/navigation';
import { useDebounce } from '@/hooks/useDebounce';

export function InventoryFilters({ total }: { total: number }) {
  const router = useRouter();
  const searchParams = useSearchParams();
  const [search, setSearch] = useState(searchParams.get('search') ?? '');
  const debouncedSearch = useDebounce(search, 300);

  useEffect(() => {
    const params = new URLSearchParams(searchParams.toString());
    if (debouncedSearch) params.set('search', debouncedSearch);
    else params.delete('search');
    params.set('page', '1'); // reset page on filter change
    router.push('/dashboard?' + params.toString());
  }, [debouncedSearch]);

  // ... rest of component
}
```

### Decisões de Arquitetura (não reabrir)
- Filtros persistidos na URL (não Zustand) — URL compartilhável e suporta back/forward
- `search` filtrado via Prisma `ILIKE` no servidor — não filtrar lista no cliente (performance)
- Filtro por `status` (available/reserved/out_of_stock) aplicado pós-query pois depende de rollup calculado
- `page` resetado para 1 ao mudar filtros — evita página inválida
