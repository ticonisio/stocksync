## Story
**As a** usuário autenticado,
**I want** um layout de navegação consistente,
**so that** eu possa me mover entre as seções do dashboard com eficiência.

## Acceptance Criteria
1. Sidebar persistente com itens: Dashboard (`/dashboard`), Insights (`/insights`), Tempo de Entrega (`/lead-time`), Configurações (`/settings`)
2. Nome e avatar do usuário visíveis no rodapé da sidebar com botão de logout funcional
3. Item de navegação ativo visualmente destacado com base na rota atual
4. Acesso não autenticado a qualquer rota protegida redireciona para `/login` (middleware já existente da Story 1.2)
5. Shell responsivo: sidebar fixa à esquerda em desktop (≥1024px); colapsável/oculta em tablet (≥768px)
6. Páginas placeholder funcionais em `/insights`, `/lead-time` e `/settings` (apenas heading por ora)
7. `<SessionProvider>` wrapping o app shell para acesso ao hook `useSession()` nos componentes

### SessionProvider Setup
[Source: `docs/architecture.md` Section 11]

```typescript
// src/app/(dashboard)/layout.tsx
import { getServerSession } from 'next-auth';
import { authOptions } from '@/lib/auth';
import { redirect } from 'next/navigation';
import { SessionProvider } from 'next-auth/react';
import { Sidebar } from '@/components/layout/sidebar';

export default async function DashboardLayout({
  children,
}: {
  children: React.ReactNode;
}) {
  const session = await getServerSession(authOptions);
  if (!session) redirect('/login');

  return (
    <SessionProvider>
      <div className="flex h-screen">
        <Sidebar />
        <main className="flex-1 overflow-auto p-6">
          {children}
        </main>
      </div>
    </SessionProvider>
  );
}
```

### Decisões de Arquitetura (não reabrir)
- Route Group `(dashboard)` garante que o shell não afete URLs — `/dashboard`, `/insights` etc. continuam iguais
- `SessionProvider` apenas no layout do dashboard (não no root layout) — evita overhead nas páginas de auth
- Páginas `/insights`, `/lead-time`, `/settings` são placeholders — conteúdo real implementado nas Epics 3 e 4
- Middleware da Story 1.2 já protege todas as rotas — o redirect no layout é uma segunda camada de segurança
