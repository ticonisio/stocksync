## Story
**As a** lojista,
**I want** fazer upload de uma planilha CSV ou XLSX com produtos comprados, ver o matching automático com meus produtos Shopify, revisar e confirmar a importação,
**so that** meu estoque seja atualizado com as quantidades importadas e eu tenha registro do custo de cada compra.

## Acceptance Criteria
1. Nova página `/imports` no dashboard exibe lista de importações anteriores (data, arquivo, status, total de itens, itens matched) e botão "Nova Importação"
2. Botão "Nova Importação" abre modal/página com área de **drag & drop** e botão de seleção de arquivo para upload de CSV ou XLSX
3. Planilha é **parseada no client-side** (Papa Parse para CSV, SheetJS para XLSX) — nenhum arquivo é enviado ao servidor, apenas os dados parseados em JSON
4. Após parse, usuário vê **tela de mapeamento de colunas**: seleciona qual coluna corresponde a "Título do Produto", "SKU" (opcional), "Quantidade" e "Custo Unitário"
5. Após mapeamento, sistema executa **matching automático** por título (case-insensitive, `contains`) contra produtos da store via API, e exibe tela de revisão com status por item: `MATCHED` (verde), `AMBIGUOUS` (amarelo — múltiplos matches), `UNMATCHED` (vermelho)
6. Itens `AMBIGUOUS` permitem ao usuário **selecionar manualmente** o produto correto de uma lista dropdown
7. Itens `UNMATCHED` podem ser **ignorados** pelo usuário (não serão importados)
8. Botão "Confirmar Importação" envia os dados para `POST /api/imports` que: (a) cria registro `Import` com status `PROCESSING`, (b) cria `ImportItem` por linha, (c) para itens MATCHED: **incrementa** `Variant.availableStock` (nunca decrementa), (d) recalcula `Variant.averageCost` como custo médio ponderado, (e) atualiza `Import.status` para `DONE`
9. Se um produto tem múltiplas variantes, o matching deve ser feito no **nível do produto** — estoque é adicionado à **primeira variante** (Default Title) ou o usuário seleciona a variante na tela de revisão
10. Após confirmação, redireciona para `/imports/[id]` mostrando o resumo da importação
11. Proteção cross-store: todos os endpoints verificam `storeId` do usuário autenticado
12. **Regra inviolável**: importação NUNCA decrementa estoque — apenas `{ increment: quantity }`

### Schema disponível (Story 9.2 — Done)
```prisma
enum ImportStatus { PENDING, PROCESSING, DONE, ERROR }
enum MatchStatus { MATCHED, AMBIGUOUS, UNMATCHED }

model Import {
  id, storeId, fileName, status, totalRows, matchedRows, createdAt
  → Store (cascade), ImportItem[]
}

model ImportItem {
  id, importId, rowNumber, rawTitle, rawSku?, quantity, unitCost (Decimal),
  matchedProductId?, matchedVariantId?, matchStatus
  → Import (cascade), Product? (SetNull), Variant? (SetNull)
}

model Variant {
  ...campos existentes...
  averageCost Float?  ← NOVO (Story 9.2)
  importItems ImportItem[]  ← NOVO (Story 9.2)
}
```

### API de busca existente
- `GET /api/products/search?q={query}` — busca por título (case-insensitive, `contains`) e SKU, retorna até 10 produtos com até 3 variantes cada. Mínimo 2 caracteres.

### Fórmula do Custo Médio Ponderado
```ts
// Para cada variante que recebe importação:
const allItems = await prisma.importItem.findMany({
  where: { matchedVariantId: variantId, matchStatus: 'MATCHED' }
});
const totalQty = allItems.reduce((s, i) => s + i.quantity, 0);
const totalCost = allItems.reduce((s, i) => s + i.quantity * Number(i.unitCost), 0);
const averageCost = totalQty > 0 ? totalCost / totalQty : null;
```

### Regra INVIOLÁVEL
```ts
// CORRETO — só incrementa
await prisma.variant.update({
  where: { id: variantId },
  data: { availableStock: { increment: quantity } }
});

// PROIBIDO — nunca usar set
// data: { availableStock: newValue }  ← PROIBIDO
```
