## Story
**As a** lojista,
**I want** que todos os meus produtos, variantes e coleções sejam importados automaticamente após conectar a Shopify,
**so that** eu possa ver meu inventário completo no StockSync sem configuração manual.

## Acceptance Criteria
1. Sync inicial disparado automaticamente quando o usuário acessa `/onboarding/syncing` pela primeira vez
2. Sistema busca todos os produtos e variantes com paginação cursor-based (`limit=250`, header `Link`)
3. Sistema busca todas as coleções (smart + custom) e associações produto↔coleção via `collects`
4. Para cada variante: armazenados `shopifyVariantId`, `productId`, `title`, `sku`, `inventory_quantity` → `availableStock`
5. Rate limiting respeitado: delay de 500ms entre requests + retry exponencial em HTTP 429
6. Tela `/onboarding/syncing` exibe progresso em tempo real via polling (`syncStatus`, `syncDone`); se `syncTotal` for null (total desconhecido com paginação cursor-based), exibir apenas "X produtos sincronizados" sem denominador
7. Sync concluído (`syncStatus = COMPLETE`): usuário redirecionado automaticamente para `/dashboard`
8. Falha no sync (`syncStatus = ERROR`): mensagem de erro exibida com botão "Tentar novamente"

### SyncService — Estrutura Geral
[Source: `docs/architecture.md` Section 6.4 — Shopify Sync Service]

```typescript
// src/services/shopify/sync.ts
import { prisma } from '@/lib/prisma';
import { decrypt } from '@/lib/encrypt';

const SHOPIFY_API_VERSION = '2024-01';
const PAGE_SIZE = 250;
const REQUEST_DELAY_MS = 500;

export async function syncStore(storeId: string): Promise<void> {
  const store = await prisma.store.findUniqueOrThrow({ where: { id: storeId } });
  const accessToken = decrypt(store.accessTokenEncrypted);
  const domain = store.shopifyDomain;

  try {
    await prisma.store.update({ where: { id: storeId }, data: { syncStatus: 'SYNCING', syncDone: 0 } });

    // 1. Sync products + variants
    let cursor: string | undefined;
    let totalUpserted = 0;
    do {
      const { products, nextCursor } = await fetchProductsPage(domain, accessToken, cursor);
      await upsertProductsPage(storeId, products);
      totalUpserted += products.length;
      await prisma.store.update({ where: { id: storeId }, data: { syncDone: totalUpserted } });
      cursor = nextCursor;
      if (cursor) await delay(REQUEST_DELAY_MS);
    } while (cursor);

    // 2. Sync collections
    await syncCollections(storeId, domain, accessToken);

    // 3. Sync collects (product↔collection links)
    await syncCollects(storeId, domain, accessToken);

    await prisma.store.update({
      where: { id: storeId },
      data: { syncStatus: 'COMPLETE', lastSyncedAt: new Date() },
    });
  } catch (err) {
    await prisma.store.update({ where: { id: storeId }, data: { syncStatus: 'ERROR' } });
    throw err;
  }
}
```

### Paginação Cursor-Based (Header Link)
[Source: `docs/architecture.md` Section 7.1 — Shopify Admin API]

```typescript
async function fetchProductsPage(domain: string, token: string, cursor?: string) {
  const url = new URL(`https://${domain}/admin/api/${SHOPIFY_API_VERSION}/products.json`);
  url.searchParams.set('limit', String(PAGE_SIZE));
  if (cursor) url.searchParams.set('page_info', cursor);

  const res = await fetchWithRetry(url.toString(), token);
  const data = await res.json();

  // Extract next cursor from Link header: <url?page_info=CURSOR>; rel="next"
  const linkHeader = res.headers.get('Link') ?? '';
  const nextMatch = linkHeader.match(/<[^>]*[?&]page_info=([^&>]+)[^>]*>;\s*rel="next"/);
  const nextCursor = nextMatch?.[1];

  return { products: data.products as ShopifyProduct[], nextCursor };
}
```

### Retry Exponencial em HTTP 429
[Source: `docs/architecture.md` Section 7.1 — Rate Limits]

```typescript
async function fetchWithRetry(url: string, token: string, attempt = 0): Promise<Response> {
  const res = await fetch(url, {
    headers: { 'X-Shopify-Access-Token': token },
    signal: AbortSignal.timeout(15000),
  });

  if (res.status === 429 && attempt < 3) {
    const retryAfter = parseInt(res.headers.get('Retry-After') ?? '2', 10);
    const waitMs = (retryAfter + attempt) * 1000 * Math.pow(2, attempt);
    await delay(waitMs);
    return fetchWithRetry(url, token, attempt + 1);
  }

  if (!res.ok) throw new Error(`Shopify API error: ${res.status} ${url}`);
  return res;
}

function delay(ms: number) {
  return new Promise((resolve) => setTimeout(resolve, ms));
}
```

### UPSERT de Produtos e Variantes por Página
[Source: `docs/architecture.md` Section 4.3/4.4 — Product/Variant models]

> **IMPORTANTE:** Usar implementação **sequencial** (não `$transaction` flat) porque o `productId` da variante depende do `id` interno do produto recém-criado. FK constraint impede usar `productId: ''`.

```typescript
async function upsertProductsPage(storeId: string, products: ShopifyProduct[]) {
  for (const p of products) {
    const product = await prisma.product.upsert({
      where: { storeId_shopifyProductId: { storeId, shopifyProductId: String(p.id) } },
      update: { title: p.title, handle: p.handle },
      create: { storeId, shopifyProductId: String(p.id), title: p.title, handle: p.handle },
    });
    for (const v of p.variants) {
      await prisma.variant.upsert({
        where: { storeId_shopifyVariantId: { storeId, shopifyVariantId: String(v.id) } },
        update: { title: v.title, sku: v.sku ?? null, availableStock: v.inventory_quantity },
        create: {
          storeId,
          productId: product.id,
          shopifyVariantId: String(v.id),
          title: v.title,
          sku: v.sku ?? null,
          availableStock: v.inventory_quantity,
        },
      });
    }
  }
}
```

### API Route: POST /api/shopify/sync
[Source: `docs/architecture.md` Section 5 — API Specification]

```typescript
// src/app/api/shopify/sync/route.ts
export const maxDuration = 60; // Vercel extended timeout

import { NextResponse } from 'next/server';
import { getServerSession } from 'next-auth';
import { authOptions } from '@/lib/auth';
import { prisma } from '@/lib/prisma';
import { syncStore } from '@/services/shopify/sync';

export async function POST() {
  const session = await getServerSession(authOptions);
  if (!session?.user?.id) return NextResponse.json({ error: 'Unauthorized' }, { status: 401 });

  const store = await prisma.store.findFirst({ where: { userId: session.user.id } });
  if (!store) return NextResponse.json({ error: 'No store connected' }, { status: 404 });

  // Run sync synchronously (within maxDuration timeout)
  await syncStore(store.id);

  return NextResponse.json({ status: 'complete' });
}
```

### Página de Syncing — Polling com useEffect
[Source: `docs/architecture.md` Section 8.3 — Initial Sync Flow]

```typescript
// src/app/(onboarding)/syncing/page.tsx
'use client';
import { useEffect, useState, useCallback } from 'react';
import { useRouter } from 'next/navigation';

type SyncStatus = 'PENDING' | 'SYNCING' | 'COMPLETE' | 'ERROR';

export default function SyncingPage() {
  const router = useRouter();
  const [status, setStatus] = useState<SyncStatus>('PENDING');
  const [syncDone, setSyncDone] = useState(0);
  const [syncTotal, setSyncTotal] = useState<number | null>(null);
  const [error, setError] = useState(false);

  const startSync = useCallback(async () => {
    setError(false);
    await fetch('/api/shopify/sync', { method: 'POST' });
  }, []);

  useEffect(() => {
    startSync();
  }, [startSync]);

  useEffect(() => {
    if (status === 'COMPLETE') { router.push('/dashboard'); return; }
    if (status === 'ERROR') { setError(true); return; }

    const interval = setInterval(async () => {
      const res = await fetch('/api/shopify/sync/status');
      const data = await res.json();
      setStatus(data.syncStatus);
      setSyncDone(data.syncDone ?? 0);
      setSyncTotal(data.syncTotal ?? null);
    }, 2000);

    return () => clearInterval(interval);
  }, [status, router]);

  // ... render progress UI
}
```

### Limitação de Timeout no Vercel Hobby
O `maxDuration = 60` requer **Vercel Pro**. No plano Hobby o limite é 10s. Para lojas pequenas (< ~50 produtos em 1 página), o sync completa dentro de 10s. Para lojas maiores, o usuário precisará de um plano Pro ou a implementação deverá usar uma abordagem de chunks menores.

Para MVP: documentar a limitação; a maioria das lojas de teste tem poucos produtos.

### Accessor Prisma para Constraints Únicas
- `Product`: `storeId_shopifyProductId` (de `@@unique([storeId, shopifyProductId])`)
- `Variant`: `storeId_shopifyVariantId` (de `@@unique([storeId, shopifyVariantId])`)
- `Collection`: `storeId_shopifyCollectionId` (de `@@unique([storeId, shopifyCollectionId])`)

### Decisões de Arquitetura (não reabrir)
- Sync é **síncrono na API route** (await syncStore) — simplicidade para MVP; Vercel Pro permite 60s
- Progresso armazenado em `Store.syncDone/syncTotal` — não requer infraestrutura adicional
- Polling a cada 2s no client — mais simples que Supabase Realtime para esta story
- Supabase Realtime para real-time ficará na Story 3.2 (dashboard em tempo real)
- `ProductCollection` usa `upsertMany` substituído por `createMany` + `skipDuplicates: true` — mais eficiente para links
- Sync de coleções ocorre **após** todos os produtos — garante que FKs existam
- `syncTotal` é nullable — paginação cursor-based não conhece o total antecipadamente; UI deve renderizar condicionalmente: `syncTotal !== null ? "X de Y produtos" : "X produtos sincronizados"`
